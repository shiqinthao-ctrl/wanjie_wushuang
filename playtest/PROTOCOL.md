# V3.3.5 真人路线验收协议

本协议只收集真人输入证据。自动化路线、AI 浏览器、390x844 模拟视口和确定性模型可以做回归，但不能替代真人、真实触控、实体手机或持续设备性能结论。

## 1. 验收路线

每种输入方式都必须完成以下五条代表路线。使用正常解锁流程；如果以后提供隔离夹具，夹具必须位于生产存档之外，并在记录中说明来源。

| 角色 | 关卡 | 目标 |
| --- | --- | --- |
| early-boss | ST001-01 边境清剿 | 06:00 前击败 B001 并领取战利品 |
| early-normal | ST001-02 废村救援 | 生存至 20:00 |
| mid-boss | ST003-03 牛魔试炼 | 20:00 前击败 B006 |
| late-normal | ST004-02 爆符峡谷 | 生存至 20:00 |
| final-dual-boss | ST004-03 炎雷双王 | 20:00 前依次击败 B009、B010 |

不要为了缩短路线而修改正式存档、浏览器存储、关卡解锁或战斗数值。建议为验收启用独立端口，以隔离现有浏览器 origin：

```powershell
$env:PORT='8082'
npm run dev
```

实体手机需要与电脑处于可信局域网，并临时监听局域网地址：

```powershell
$env:HOST='0.0.0.0'
$env:PORT='8082'
npm run dev
```

用电脑的局域网 IPv4 地址访问 `http://<电脑IPv4>:8082/`。测试结束后关闭服务；不要在公共网络暴露此端口。

## 2. 三类证据分别完成

1. `keyboard-mouse`：真人使用键盘和鼠标，不能用脚本代按。
2. `browser-touch`：真人在支持真实触控的浏览器设备上操作，DevTools 触控模拟不算。
3. `physical-device-touch`：真人在实体 iOS/Android 手机上操作，必须记录型号、系统、浏览器、持续性能和热感。

每一类至少有一个 `completed` session，并在该 session 内完成五条路线。不同类别不能由同一条自动化记录互相替代。

## 3. 每条路线必须记录

- 结果、尝试次数、死亡次数、重试次数、完成时间、结算血量余量。
- 英雄、装备和关键构筑选择。
- 1-5 分：移动/瞄准、威胁清晰度、命中清晰度、闪避响应、技能响应、恢复公平性、构筑质量、疲劳。
- 文字观察：移动/瞄准、威胁与命中、闪避与技能、恢复、构筑、死亡/重试、疲劳。
- 至少一个证据引用，例如录像文件名、截图文件名或带时间戳的人工观察记录。

评分锚点：`1` 表示严重阻碍完成，`3` 表示可完成但问题明显，`5` 表示清晰、稳定且无需调整。不要只写分数；任何调参建议必须能追溯到具体路线、输入方式和观察。

## 4. 实体手机附加记录

- 至少连续记录 20 分钟的性能窗口。
- 记录平均 FPS、最低观测 FPS 和测试后的热感。
- 记录横竖屏、刘海/安全区、双指同时操作、暂停/恢复是否可靠。
- 模拟器或 390x844 视口不得把 `physicalPhoneConfirmed` 标为 `true`。

## 5. 填写与校验

复制 `playtest/session-template.json` 到一个新的验收记录文件再填写；模板本身始终保持 `pending`。记录文件位于生产存档之外，不会被游戏加载。

```powershell
npm run playtest:self-test
node scripts/playtest-validate.mjs playtest/<记录文件>.json
node scripts/playtest-validate.mjs playtest/<记录文件>.json --require-acceptance
```

- 普通校验允许结构正确的 `pending` 记录，并明确输出 `PENDING`。
- `--require-acceptance` 只有三类真人 session 均完成五条路线时才通过。
- 校验器拒绝自动化冒充真人、模拟器冒充实体手机、缺少指标或缺少证据引用。

## 6. 调整与复验门槛

只有实际观察到输入延迟、精度、命中反馈、危险预警、动作时序或不公平/无意义难度峰值，才能修改现有反馈、时序、遭遇或难度值。每次调整记录修改前观察、最小改动和修改后同路线复验；不得新增内容、隐藏强度、存档字段、公开 Debug UI 或包装层。

完成真人记录后，仍需运行项目五项门禁，并只在证据满足时把 V3.3.5 标为真人验收完成。
