# R1g-13 — 不躲的代价：scope 与判定（零生产改动）

Base: R1g-12。决策正文见 `tasks/game-remediation/DECISIONS.md` **D11**。
本片**不改任何生产数值**，交付 = 一个显式判定 + 两处措辞。

---

## 0. 一行结果

R1g-9 的「一个不读预警、不按闪避的玩家**必死**」在 R1g-12 的杂兵表上不再成立；
本片判定这**不是缺陷**：同一批 66 局/臂的 `losses` 分解显示，**不躲让战死率从 12.1% 涨到 27.3%
（2.25×）**，血线 0.449 → **0.202**、胜率 87.88% → **71.21%**，并跌破 G2 下沿。
惩罚从**悬崖**变成**斜坡** —— 这是更好的设计，措辞按此改写，**不动 Boss 旋钮**。

## 1. 前提（Scope 0 核实，三条全部成立）

| # | 前提 | 证据 |
|---|---|---|
| 1 | 「不躲」的代价里**四分之三来自杂兵** | `browser` 臂单局承伤 Boss **319** vs 杂兵 **996** HP ⇒ Boss 份额 **25.25%**（`bossShareMedian`） |
| 2 | **招式侧是常数**（G4 把最弱招钉在 15%） | `bossSkillDamage = 14.31` ⇒ 最弱招 **15.00%**；`TASK.md` 明说 G4 的定义不许动 |
| 3 | **体接触不可读、不可躲** | 由 `bossContactInterval`（1.1s）驱动，站得近就吃；唯一自由旋钮是 `bossDamage 0.6 × bossContactDamage 0.8` |

数据源：`evidence/R1g-12/boss-hud-arms.json`（`after` 段）。

## 2. 判定：(b) 分档惩罚是正确设计

| 臂 | 血线中位 | 胜率 | **战死** | 超时 |
|---|---|---|---|---|
| `hud`（读预警 + 按闪避） | **0.449** | 87.88% | **8/66 = 12.1%** | 0 |
| `browser`（不读预警、不躲） | **0.202** | **71.21%** | **18/66 = 27.3%** | 1 |

「惩罚」没有消失，只是从**悬崖**变成**斜坡**。斜坡更好，理由是实测的：
R1g-11 落地前，一个**认真读预警**的玩家 **66 局里 64 局超时**（血线 0.761 却打不死 Boss）
⇒ **「读懂了会输」，最优解是站桩硬吃**。悬崖会把「躲」变成负收益。

## 3. 为什么不是 (a)（把惩罚重新挂到 Boss 招式上）

- **算术**：把 `browser` 推归零需再扣 ≈20% 生命 ≈ **152 HP/局**。招式侧被 G4 钉死 ⇒ 只能全压在
  体接触上 ⇒ `bossContactDamage` 0.8 → **≈1.55**。`hud` 臂体接触同步 ×1.94 ⇒ 血线 0.449 → **≈0.26**，
  **贴着 G2 的 0.25 下沿**。**用「会躲」那一臂的全部余量，去买一个只在「不躲」那一臂成立的锐度。**
- **设计**：体接触**不可读、不可躲**。挂上去教的是「站远」，不是「读预警、按时闪避」——
  而后者才是 P0-4 / G4 存在的理由（R1g-9：Boss 缺的是**单招可读性**，不是总量）。

## 4. `bossContactDamage = 0.8` 的再决策 —— **保留**

R1g-11 的理由（1.0 时 `hud` 0.240 < 0.25）在 R1g-12 的杂兵表上**已不成立**（1.0 → 0.414）。
本片判定保留 0.8，因为：

- 它移动不了任何**设计主张**（0.8 → `browser` 0.202；1.0 → ≈0.15；两者都 < 0.25，定性相同）；
- 它移动不了 `hud` 的**定性**（0.8 → 0.449；1.0 → 0.414；都在带内）；
- ⇒ 按「没有理由就不动数值」保留，并给记录臂留 **0.199** 余量。

**身份变化（必须记）**：0.8 从「**最小可行改动**」变成「**保留余量**」。

## 5. 本片**不**重跑 harness、**不**重指输出目录

`TASK.md` 的 Scope 3 要求重跑四个 harness。本片**不重跑**，理由：

- 本片**零生产改动**，而 harness 是**树的确定性函数**（固定种子）⇒ 重跑只会复现同一批数字；
- `evidence/R1g-12/` 的报告**仍然是当前树的读数**（因为树没变），重指到 `evidence/R1g-13/`
  只会把同一批数字复制一遍，并给下一位制造「R1g-13 有自己的读数」的错觉；
- 同片的全量 vitest 套件就是这条确认，读在**未改动的树**上：`bossThreat` 9/9、
  `bossBudget` 9/9、`threatModel` 12/12、`manualDamage` 10/10（另加 `skillCadence` 6/6、
  `growthPacing` 7/7、`fusionReachability` 5/5）。

这与 R1g-8 / R1g-9 的做法**不同**：那两片各自**新建了仪器**，所以需要新目录；本片没有新仪器。
