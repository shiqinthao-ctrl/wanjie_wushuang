# R2-F-BOSSPHASE —— 招式序是相位的函数，而相位是玩家 DPS 的函数

**一句话**：`FirstBoss.ts:106` 用 `config.mechanics.skills[(boss.skillIndex + boss.phase - 1) % 3]`
选招，而 `boss.phase`（`:70`）是 `ratio <= .35 ? 3 : ratio <= .70 ? 2 : 1` —— 它随 **Boss 剩余血量**
推进，也就是随**玩家已经打出的伤害**推进。`boss.skillIndex` 本身（`:105`，`(skillIndex + 1) % 3`）
是一条干净、可学的循环；**加上相位项之后，同一个施放序号会解析成不同的招式**，取决于这一局的
血量轨迹。**本片零生产改动**，只把这条规则**测出来并钉住**，不修——修法要动一份承重标定（见 §2）。

## 0. Scope 0 —— 前提核实

### 0.1 三处现场（逐字引）

| 位置 | 原文 |
| --- | --- |
| `:105` | `boss.skillIndex = (boss.skillIndex + 1) % 3;` |
| `:106` | `const [type, name] = config.mechanics.skills[(boss.skillIndex + boss.phase - 1) % 3]!;` |
| `:70` | `const ratio = boss.hp / Math.max(1, boss.maxHp), phase = ratio <= .35 ? 3 : ratio <= .70 ? 2 : 1;` |

### 0.2 招式表（`firstBoss.json.mechanics.skills`，**常量**，表序即槽位）

| 槽 | 形状 | 名 |
| --- | --- | --- |
| 0 | `circle` | 震地斩 |
| 1 | `line` | 蛮王冲锋 |
| 2 | `cone` | 旋风断军 |

相位名（`mechanics.phase`）：`巨斧压境 / 蛮王狂怒 / 震岳绝境`。

### 0.3 `phase` 有两个角色，只有一个是非法的

**合法（承重，必须留）** —— 相位让战斗**变难**：

| 位置 | 相位做什么 |
| --- | --- |
| `:107` | 招式伤害 `13 + phase * 4` |
| `:111` / `:118` / `:121` | 预警半径 `86 : 70`、冲刺宽 `54 : 44`、扇形 `230 + phase*25` / 张角 `.72π : .55π` |
| `:107` 的 `delay` | `max(.55, .95 - phase*.08)` |
| `:97` | Boss 移动速度 `38 + phase*7` |
| `:124` | 冷却 `max(.9, (3 - phase*.38)/speed)` |
| `:103` | 接触伤害 `11 + phase*3` |

**非法（本片的缺陷）** —— `:106` 把相位**加进招式下标**，于是**顺序**随血量改。

### 0.4 GDD 要的是什么（`docs/design/GDD-可玩性提升设计-v2.md`）

- `:325` G3 的验收 = 「**60–90 秒**，三阶段各至少一次」 ⇒ 要的是**三个相位被走到**，不是招式顺序。
- `:433` 「三招各命中一次 ≈ 66% 最大生命」是 **G4 的伤害目标**（每招都够疼），也不是顺序。

⇒ **没有任何设计要求「招式顺序随 DPS 变」**；那句话没有主人。

## 1. Scope 1 —— 相位项在防什么

**它防的是「表格下标越界 / 顺序固定」，而那个担忧是假的。**
`(skillIndex + phase - 1) % 3` 里的 `% 3` 无论有没有相位项都在，所以相位项**不防越界**。
它唯一的效果是**把顺序从 `skillIndex` 平移 `phase - 1` 格**——
而 `phase ∈ {1,2,3}` 让这条平移量**每场都在变**。

`skillIndex` 单独就已经是一条干净的三步循环，且**相邻两刀永不重招**（`+1 % 3`），
这正是 `bossThreat.test.ts:249-250` 那条注释声称「后缀永不连续重复」所依赖的性质 ——
**但那条注释把机制归因给了 `(skillIndex + phase - 1) % 3`，而它真正依赖的只是 `+1 % 3`**。
相位项在这里是**多余的**。

**⇒ 注释声称的机制 ≠ 代码实际依赖的机制。** 解释一条性质前先把它的**最小充分条件**找出来；
多出来的那一项**必须有它自己的防守对象**，否则它就是**把一个旋钮渗进了正交维度**。

**结论**：相位项在 `:106` 上没有防守对象，它只是把相位（一个「难度」旋钮）**渗进了「顺序」这个
正交的维度**。

## 2. Scope 2 —— 两个修法形状的定价

### (a) 去掉相位项 —— **但它不是「删掉」，是「平移一格」**

`skillIndex % 3` 与 `(skillIndex + phase - 1) % 3` 在 `phase = 1` 时**相差一格**：

| `skillIndex` | 现规则（相位 1） | 去相位项 | 改变？ |
| --- | --- | --- | --- |
| 1 | 蛮王冲锋 | 震地斩 | **是** |
| 2 | 旋风断军 | 蛮王冲锋 | **是** |
| 3 | 震地斩 | 旋风断军 | **是** |

**作废的早期标定（承重）**：`formPressure.test.ts:1616-1617`（及两个同形副本 `:1854-1855`、
`:2107-2108`）断言首领格里 **`B001-蛮王冲锋` 与 `B001-旋风断军` 都打中**，
而 R2-F-INST 在 `:1613` 写明了理由：*「two casts, the charge then the cone, both at phase 1」*——
即 `(skillIndex + phase - 1) % 3` 的槽 1 与槽 2。**改成 `skillIndex % 3` 会把这两条断言各平移一格**
（槽 1 → 震地斩、槽 2 → 蛮王冲锋），**三处断言全部要改写**。

**正确做法不是「删相位」，而是「把循环起点钉死」**：若要顺序可学，应写成
`skills[skillIndex % 3]` 并**同步改写那三处标定**（把 `蛮王冲锋/旋风断军` 换成新槽位的招式名），
账单是一次性的、且可枚举。

### (b) 保留但断言「每相位产出什么顺序」 —— **本片做法**

不动生产，把「顺序由 `(skillIndex, phase)` 共同决定」写成断言：
整张 3×3 表、第一刀的三相位三招式、`skillIndex` 单独是干净循环、去相位项平移一格、
以及**反事实 58/61 与 59/59**。这样任何改动 `:106` 或 `:70` 的人**立刻看到红了什么**。

### G4/G3 是否移动

**都不动**：本片只加仪器。`G4` 的伤害读数与相位无关（它读 `lost / maxHp`）；`G3` 只读时长窗口与
相位推进，而相位**推进规则**（`:70`）没改。
