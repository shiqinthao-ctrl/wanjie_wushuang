# R2-F10 — `windwarden`（岚影剑尊 H012）四压力场景行为验证

**结论：零生产改动。** 加 1 条 `SPECS` + 2 个 `describe`（7 测试，其中 5 条身份 + 2 条压力）。
`Outcome` **没有长键**（本形态同样没有 `fields` 条目）⇒ **九份**旧报告用**直接 md5** 复核，逐位相同。

`windwarden` 是 H012 四形态里的**第四个**，也是**十个形态里的最后一个**。它是系列里**第一个
同时抬起两个容器的 kit**：`:68` 与 `:89` 都是 `fixedVortex` 调用（落在 `vortices`），而 `:85`
那条独立 `if` 召 `H012_R_CLONE`（落在 `summons`）。⇒ `vortexPeak` 与 `summonsPeak` **第一次
同时非零**，而且两个都不是 `> 0` 能读的：涡旋峰值恰好 **2**（每次施放一个，都在第 0 帧），
召唤峰值就是克隆数 **4/5**（这个 kit 的召唤半边离 `cap(summons, 8)` 远得很）。

本片的主发现是**两个涡旋互相遮蔽**（§5.1）—— 它把「觉醒在敌群格值多少」这个问题从「一个数」
变成了「一个 0」。

## 5. 发现

### 5.1 本片主发现：两个涡旋**互相遮蔽**，把敌群格变成逐位相同

`:68` 与 `:89` 都在**第 0 帧**施放，而 `fixedVortex` 的方向来自 `nearestFrom(p)` —— **同一个
函数、同一帧、同一个敌人集合** ⇒ 两个涡旋落在**同一个点**（探针实测：都在 `(1920, 1200)`）。
必杀半径 **200** 严格包含技能的 **120/160**。

然后 `updateVortices`（`CombatSimulation:489`）是**倒序**遍历的：

```
for (let i = this.vortices.length - 1; i >= 0; i--)
```

数组顺序是 `[G4_WIND_E, G4_WIND_R]` ⇒ **必杀先结算**。而 `EN001` 的 **hp = 63**、必杀一跳
**98.96 原值** ⇒ **一跳致死**。于是每一次 tick，必杀都把技能**够得到的东西**先杀光：

| 格 | 必杀一跳是否致死 | `G4_WIND_E` | 觉醒可见吗 |
| --- | --- | --- | --- |
| 敌群 | ✅ 致死（63 < 98.96） | **完全不出现** | ❌ **逐位相同** |
| 精英 | ❌ 不致死（`EN006` 血厚） | 110.84 | ⚠️ 可见但被「一具身体」吃掉 |
| 首领 | ❌ 不致死 | 1662.56 → 2050.49 | ✅ 可见 |

- 敌群格 `G4_WIND_E` **从头到尾一次都没进过 `damageBy`**（不是「很少」，是**没有键**）。
- ⇒ 觉醒把技能半径 120→160、时长 4→6，**在敌群格里一个字节都换不来**（1319.7586989600002
  两阶逐位相同）。**这不是数值不够，是规则让技能永远晚一步。**
- 这是「**净增量掩盖反向分量**」的**同一类错的第三个面**（前两个：R2-F09 的守卫换分身、
  R1g-11 的聚合中位数）：这次的掩盖方式更彻底 —— **总量直接相同**。

### 5.2 轴上那道刃让远程格第一次被**普攻**拿下

R2-F07/F08/F09 的 control 在远程格**恰好 0**，因为两刃扇形 `±0.115` 把 `heroAim()` 锁定的目标
放在缝里（520px 处离刃线 `520·sin(.115)` = **59.6px** ≫ 17px 接触半径）。F10 的第三道刃在
**轴上**，所以：

- kit 的 `H012_BASIC` 贡献 **223.34**（`heroAim()` 直接命中）；
- control 的 `dealt = **670.01**`、`killed = **6/6**` —— 普攻**单独就能清掉整条线**。

这是本片第二个「**同一份 kit 规则，因为一个几何细节而换了一整格的语义**」的例子（第一个是
`pierce` 的深度）。它同时说明：**远程格在 F07..F09 上读到的「kit 无法触及」不是 H012 的共性，
而是那三个扇形形状的性质。**

### 5.3 一个正增量里藏着一个反向分量（远程格）

远程格 r1 → r2 是 **+7.80%**，但拆开看：

| 分量 | r1 | r2 | 方向 |
| --- | --- | --- | --- |
| `H012_R_CLONE` | 750.53 | **938.16** | ↑ +25% |
| `H012_BASIC` | **223.34** | 111.67 | ↓ **−50%** |

机制：第五个分身让整条线**更早死**，于是自动普攻（0.833s 一跳）的后续几跳**找不到活靶**。
`taken` 从 65.38 掉到 **49.04** 也是同一件事的另一面。

⇒ **凡「觉醒让 X 上升」的句子，都要先拆 `dealtBy`**：本片这里两个分量方向相反、幅度都不小，
聚合比值（1.078）把 −50% 那一半完全藏住了。

### 5.4 `G4_WIND_E` 以 `_E` 结尾 —— 「无手动释放」的过滤器**不能**写成裸 `endsWith('_E')`

`_E` 是手动释放的遥测后缀（`CombatSimulation:218`：`key = manual ? `${source}_E` : source`），
而**每个形态的技能 id 都以 `_E` 结尾**（`EvolutionCombat:61` 生成 `${heroId}_E`，形态 kit 是
`G4_WIND_E` / `G5_FROST_E` / `G2_FROST_E` / `H001_E` …）。

R2-F09 引入的「no manual release fired」断言写成裸 `endsWith('_E')` **在 beastlord 上是对的**，
只因为那一片的 `kit` 恰好是唯一**不含 `_E` 结尾 id** 的形状。本片第一次跑就红：

```
elite/r1: no manual release fired: expected [ 'G4_WIND_E' ] to deeply equal []
```

**这不是「有手动释放」，是同一个字符串被读了两种意思** —— 与 `H012_BASIC` 四方共用键是同一类
陷阱。修法：过滤时排除 kit 自己的 id。

### 5.5 装饰环借用 kit 自己的 id（第三次）

`fixedVortex` 结尾是 `s.ring(point, radius, id)`（`:124`），`id` 就是 `G4_WIND_E` / `G4_WIND_R`。
`ring`（`:175`）只 push 事件 ⇒ **零伤害**，但事件流里出现的是 kit 自己的名字。R2-F09 的 `:92`
是同一形状（借分身 id）。本片把它写成断言：**施放帧两个 id 在 `damageBy` 里都是 `undefined`**，
且环半径恰好等于涡旋半径。

### 5.6 形态风阵**不吃**面积加成 —— 与 A026 不一致，但是设计意图

`fixedVortex` 把 `radius` **原样**传给 `vortex`；而 `cast()` 里的 `A026`（本形态的**签名技能**，
`signatureSkills.windwarden = 'A026'`）会乘 `skillModifier(...).range`：

| 来源 | 半径是否乘 `m.range` |
| --- | --- |
| 形态 kit `G4_WIND_E` / `G4_WIND_R` | ❌ 原样 |
| `A026`（签名技能，走 `cast()`） | ✅ 乘 |
| R2-F09 的近卫爆（`125 * skillModifier(...).range`） | ✅ 乘 |

⇒ 同一个形态里，**装备/天赋的面积加成只放大签名技能，不放大 kit 风阵**。本片**不改**它（scope
外），只记录：这是「形态 kit 的强度不随 build 成长」的一个具体表现，和 G8 的结构问题同源。

### 5.7 首领格仍在测一个「10 秒内不出手的 Boss」（全系列，非本片）

十片全中 `bossCasts = 0`。原因是 R1g-10 的 `bossCastCooldown = 14.31` 把首跳推到窗口之外，
**不是**「Boss 不会打人」。这条已由 **R2-F-INST** 立项（§9）。
