## 0. Scope 0 — 前提核实

### 0.1 敌群格的构造

`formPressure.test.ts:368`：

```ts
horde: (sim: CombatSimulation) => onRing(sim, 'EN001', 120, 12),
```

`onRing`（`:335`）把 `count` 具身体放在以**玩家**为心、半径 `radius` 的圆上，均匀分布
（`offset + i/count * 2π`）。

| 量 | 值 | 是常量还是测量 |
| --- | --- | --- |
| 环半径 | **120px** | **常量**（写在 `scenarios.horde` 里） |
| 身体数 | **12** | **常量**（同上） |
| 身体 id | `EN001`（黄巾步卒，`ai: melee`） | **常量** |
| 角步长 | **30°**（`2π/12`） | **测量**：`it` 1 从 `scenarios.horde(sim)` 逐具读回，`Math.min/max` 都是 `π/6` |
| 环半径实测 | 12 具全部 **120.000000px** | **测量**：同上 |
| **身体 HP** | **63** | **测量**：`createEnemy` 把目录里的 `cfg.hp = 70` 乘上关卡 `firstStage.hp = 0.9`（本格 `time = 0`、难度 `normal`）⇒ **63**。目录的 70 **不是**场上的数 |
| 环心 | 玩家坐标 | 常量：`onRing` 用 `sim.player.x/y`；`run()` 全程不移动玩家 |

> **角步长是这一格的性格**：30° 的离散环上，「半径从 r 涨到 r′」只有在
> `2r·sin(Δ/2)` 跨过某个身体时才改变覆盖数。`Δ = 90°` 处弦长 `2·120·sin45° = 169.7`，
> 而岚影的觉醒把技能涡旋从 **120 推到 160** —— **160 < 169.7，一具都不多**。这就是「第 0 帧中性」。

### 0.2 觉醒真正推动的那个「第 0 帧离散量」

本格在第 0 帧就**结算**：两个 `fixedVortex` 都以 `tick: 0` 入列，`updateVortices`
（`CombatSimulation:497`）在入列后的第一帧就跳一次，之后每 **0.28s** 一跳。所以一格能看见什么，
取决于**觉醒有没有改变「第 0 帧那一次结算覆盖到几具身体」**。

| 形态 | 觉醒动的是什么 | 第 0 帧离散？ | 敌群格可分？ |
| --- | --- | --- | --- |
| `bulwark` | 场 r 170→210、护盾 .16→.24 | 否（两阶都覆盖满环） | 否 |
| `frostlord` | 霜场 r 160→200、时长 3→5 | 否 | 否 |
| `frostflame` | 霜 r 180→220、火场 r 130→180 | 否 | 否 |
| `phoenix` | 普攻扇 **3→5 片** | **是** | **是** |
| `legion` | 召唤 **2→3**、必杀 **4→5** | **是**（但本格不触发） | 否 |
| `thunderlord` | 链 **5→7 跳** | **是** | **是** |
| `void` | 技能涡旋 r **110→145**，跨过 120px 环 | **是** | **是** |
| `reaper` | 普攻弧 1.4π→2π、技能弧 160 | 是（本格不触发） | 否 |

## 1. Scope 1 — 互斥的实测

`it` 2 读**十份在盘压力报告**（不是重跑），把每个 (形态, 格) 分成 `clean × blind`：

```
clean = hpMin(r1) == 1 且 hpMin(r2) == 1
blind = 两阶的 dealtBy 是同一组来源、同一组数值
```

| | blind | 可分 |
| --- | --- | --- |
| **clean** | **17** | **4** |
| **dirty** | **8** | **11** |

**⇒ 「clean ⟺ blind」不是规律：40 格里有 12 个反例，两个方向都有。**

| 方向 | 反例（逐格） |
| --- | --- |
| clean 但**可分** | `phoenix/horde`、`thunderlord/horde`、`void/horde`、`void/elite` |

**敌群列本身**：十个形态**全部 clean**（`hpMin` 两阶都是 1），其中 **3 个可分**
（`phoenix` / `thunderlord` / `void`）。⇒ TASK 的「the horde cell cannot distinguish the
awakening of a field form **at all**」**按字面是假的** —— `void` 也是持续场，它的敌群格分得开。

**而且敌群格不是最弱的格**：

| 格 | 十形态中 rank-blind 的个数 |
| --- | --- |
| `horde` | 7 |
| `ranged` | 8 |
| **`elite`** | **9** |
| `boss` | 1（只有 `thunderlord`） |

⇒ 「敌群格看不见觉醒」是**系列常态**，而且**精英格更差**。这一点 R2-F-SHADOW §3 已经量到，
本片把它做成了可复算的扫描。

### 1.1 那六值扫掠为什么「无一例外」

TASK 引用的六值扫掠（R2-F-SHADOW §2）只动了**一个杠杆**：必杀一跳的伤害系数。它的结果是对的，
而且本片给出了机制（R2-F-SHADOW 给的是机制的一半）：

1. 必杀 200px 盘在第 0 帧覆盖环上 **7/12**（`2·120·sin(Δ/2) ≤ 200 ⇒ Δ ≤ 112.9°`）；
2. 剩下 **5 具**在盘外（`Δ ≥ 120°` ⇒ ≥ 207.8px），**被 85px/s 的向心牵引拖进盘内**
   （`CombatSimulation:494`，作用半径 `r·1.5 = 300px`，叠加它们自己的 65.28px/s）；
3. 致死时它们在第 **2 跳**（`0.28s` ⇒ frame 17）清空 ⇒ 玩家零伤；
4. 不致死时每只要 **2–3 跳** ⇒ 有身体活到 0.3s 之后 ⇒ 玩家挨 **18.68**。

⇒ **「必杀对杂兵致死」既是「无伤」的成因，也是「觉醒不可见」的成因**，因为觉醒的两条通道都在
这个窗口之外：

- **技能涡旋**：`:68` 与 `:89` 都调 `fixedVortex`，两者都以 `nearestFrom(p)` 为目标 ⇒ **落在同一点**，
  必杀 200px 盘**严格包含**技能 120/160px 盘，而 `updateVortices`（`:489`）**倒序**遍历 ⇒
  必杀永远先结算 ⇒ 环上一具都不剩给它 ⇒ `G4_WIND_E` **恒 0**（`it` 3 在 150px 上复验了这条仍然成立）。
- **第 5 个分身**：`summon` 的 `tick = .12 * i` ⇒ 第 5 个（r2 独有）第一跳在 **0.48s**，
  而环在 **0.283s** 就死光了 ⇒ 它没有目标。

⇒ TASK 的「the five bodies outside the 200px disc each have to die to one jump…」**逐字成立**，
本片把「一跳 / 两跳」补成了 **0.28s 的跳周期**与 **0.48s 的分身首跳**两个可复算的时间点。

## 2. Scope 2 — 定价：敌群格扛着什么

### 2.1 它扛着两条，只有一条是「觉醒」

| 断言 | 它实际断言的是什么 | 十形态里谁在读 |
| --- | --- | --- |
| `hpMin === 1` | **成本**：这个 kit 清掉 12 具身体**不掉血** | 7（F04..F10） |
| `killed === of` / `absorbed + taken === 0` / `basicDealt === 0` | **覆盖与速度**：环在第 0 帧就被清掉 | 10 / 10 / 6 |
| `r2.dealtBy toEqual r1.dealtBy` | **一个否定命题**：「觉醒在这里看不见」 | 3（F08/F09/F10） |

**关键**：对 F08/F09/F10，敌群格的「盲」**是被断言的**，不是沉默的 —— 它们把仪器的局限写成了
一条**设计事实**（`F10` 的注释原文：「the awakening cannot show here」）。
⇒ 这里**不是**「描述性字段没人断言」那种烂法；缺的**不是**断言，是**一格能显示它的场地**。

### 2.2 缺口的真实价格：谁还扛着这条

对每个形态数一数**四格里哪些分得开**：

| 形态 | 分得开的格 | 个数 |
| --- | --- | --- |
| `bulwark` | `boss` | 1 |
| `frostlord` | `boss` | 1 |
| `frostflame` | `boss` | 1 |
| `phoenix` | `horde`、`boss` | 2 |
| `legion` | `ranged`、`boss` | 2 |
| **`thunderlord`** | **`horde`** | **1** |
| `void` | `horde`、`elite`、`boss` | 3 |
| `reaper` | `boss` | 1 |
| `beastlord` | `boss` | 1 |
| `windwarden` | `ranged`、`boss` | 2 |

⇒ **十个形态里有六个，首领格是唯一分得开的那一格**；只有 `thunderlord` 靠敌群格。
`windwarden`（本片的主角）**不靠**敌群格 —— 它在 `ranged` 与 `boss` 上分得开。

**所以缺口的定价是**：敌群格的「盲」对 `windwarden` 的**觉醒可见性**并不致命（另有 2 格扛着）；
真正被敌群格**唯一**扛着的是**「12 具身体的多目标清线成本」**这条 —— 四格里只有它有多目标
（`ranged` 有 6 具，`elite` 1 具，`boss` 1 个）。**觉醒在多目标下的行为**只有 `horde` 与 `ranged`
两格能读，而 `ranged` 对 8/10 形态是盲的 ⇒ **觉醒的多目标行为，对 7 个形态只在 `horde` 一格上被读，
而那一格读不到。**

### 3.3 `clean` 对半径**非单调** ⇒「挑一个半径」不是设计

```
半径   120   150   180   210   240   260   280   300
clean  ✅    ✅    ❌    ✅    ❌    ✅    ✅    ✅
```

180 收 18.68、240 收 9.34，而 150 / 210 / 260 / 280 / 300 一分不收。
原因是**一场赛跑**，不是一个距离阈值：远侧身体既被必杀盘拖、又朝玩家走，
「它先死」还是「它先碰到玩家」由 **0.28s 的跳周期**与它自己的 65.28px/s 决定。
⇒ 一次半径调整能让今天的答案翻面；**这不是可以靠调参钉住的东西**。
