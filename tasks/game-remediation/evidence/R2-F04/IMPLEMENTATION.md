### 行为逐条

1. **普攻是「3 道（觉醒 5 道）扇形火羽，每道带 28px 爆」**：一次 `basic()` 后
   `projectiles.filter(id === 'H010_BASIC')` 长度 = **3 / 5**；每道的 `explode = 28`、`pierce = 0`、
   `dmg = atk × .65`、速度 = **440px/s**；航向**等间距 0.23 rad**、关于瞄准方向对称
   （rank 1 开合于 ∓0.23，rank 2 于 ∓0.46）。
   **爆的射程用旁观者行为验证**：目标放在 +200px 的瞄准线上（`r=10`，火羽 `r=7` ⇒ 直击需
   弹道过其 17px 内；+200px 处扇羽落在 y = 0 / ±46.8 / ±99.5，所以 20px 与 72px 两个旁观者
   **都不在任何弹道上**）。跑 40 帧（0.667s，**短于自动普攻最小间隔 1s**）后：
   **20px 的旁观者掉血（只有爆能碰到它）、72px 的不掉**，且直击目标掉得更多
   （直击 + 爆 vs 只有爆）——**「28px 爆」是可证伪的，不是读调用参数。**
2. **技能 = 150px 突进 + 5 个静止火径 + 一圈 150px 全周环**：`action('skill')` 后
   ①玩家沿瞄准方向**精确位移 +150px**；②`fields.filter(id === 'H010_E')` 长度 = **5**，
   每个 `r = 48`、`life = 2.5 / 4`、`dmg = atk × .22`、`follow === false`、`chill === undefined`；
   ③把玩家挪 260/180px 后**火径坐标逐位不变**。
   **全周环的证伪形式**：环是在**突进之后**结算的（`dash` 先动玩家，`arc` 再以新位置为心），
   所以预先放在 +20px 的敌人突进后落到玩家**正后方 130px** ——
   默认技能弧是 **1.35 rad**，正后方（delta = π）落在它之外；实测它**掉血**，证明这是 2π 环。
   同时 +304px 的敌人（离新圆心 154px）**不掉血**，钉住半径 150。
3. **必杀 = 16 道全周火羽，且不留任何场**：`player.ult = 100` → `action('ultimate')` 后
   `projectiles.filter(id === 'H010_R')` = **16**，航向间隔 π/8、速度 340px/s、`dmg = atk × 2.4`、
   `pierce = 2`（= 打 3 个）、`explode = 65`；**`sim.fields` 长度为 0**（见 §5.1）。
   行为验证：四个正方向（东/西/南/北）200px 的敌人**全部掉血**（它们正对第 0/8/4/12 道羽）。
4. **觉醒只动两处**：普攻 3→5 道、火径 life 2.5s→4s；**火径半径 48 两阶相同**、
   **必杀 16 道两阶相同**。`fieldMax` 在四场景都变大、`fieldR` 在四场景都不变（两条断言都进报告）。
   在**首领格**这一项有可测价值：**13240.15 → 21084.46（+59.25%）**
   （普攻 8082.25 → 13470.41，正好 **5/3 = +66.7%**）。

## 3. 单一开关对照：技能本身（`kit: false`）

本形态**没有状态、也没有护盾**，所以唯一能撤的开关就是技能/必杀本身。
对照跑在**敌群**与**远程**两格（rank 1）：

| 格 | `casts` | 造成伤害 | 其中普攻 | HP 承伤 | `hpMin` | 首次命中 |
|---|---|---|---|---|---|---|
| 敌群（**kit 开**） | 2 | 4105.67 | 544.26 | **0** | **1.000** | **0s**（4 只） |
| 敌群（**kit 关**） | **0** | 1719.86 | 1719.86 | **84.06** | **0.836** | 1.05s |
| 远程（kit 开） | 2 | 1088.52 | 1088.52 | 81.73 | 0.842 | 1.67s |
| 远程（kit 关） | 0 | **1088.52**（逐位相同） | 1088.52 | **98.08** | 0.810 | 1.98s |

- **敌群格是正结果，而且是本系列第一个。** F01/F02 的敌群格都被单一开关反事实判成
  **不具判别力**（环一次清空，有没有 kit 一样）；F03 的敌群格同样（霜环一击清空）。
  `phoenix` 不同，因为**它的普攻是扇形**（±0.23 rad = 26°），扇形盖不住一个环。
  撤掉技能后：承伤 **0 → 84.06**、`hpMin` **1.000 → 0.836**、首次命中 **0s → 1.05s**。
- **但判别量是「承伤」而不是「击杀」。** 两臂的 `killed` **都是 12/12** ——
  扇形只是慢，10 秒内照样清空。如果按 F01 的写法去断言 `control.killed < control.of`，
  这一格会被**误判成不具判别力**，正结果就丢了。这条写进了断言与注释。
- **远程格是负结果，且说明它到底在量什么**：`kitDealt` 两臂**逐位相同（1088.52）**，
  `dealtBy` 里**只有 `H010_BASIC`**（`H010_E` / `H010_R` 连 0 都没有）⇒
  **这一格量的是普攻的 880px 射程，不是 kit。** 技能环 150px、火径 48px，
  而远程线停在 190–300px（`enemyAI`）⇒ 两者都够不着。
  kit 在这一格唯一的贡献是**突进的 2 × 0.25s 无敌帧**：98.08 → 81.73。

## 5. 规则发现（都进队列，不在本切片改）

### 5.1 TASK.md Scope 2 的「必杀留下一个跟随火域」是**假的**

`:94` 与 `:95` 是同一个 `else if` 链上的相邻两行：

```ts
else if (v.heroId === 'H010') for (let i = 0; i < 16; i++) s.projectile(...);   // :94 ← phoenix 走这里
else { s.arc(260, p.atk * 8, id, Math.PI * 2); s.field(id, p, 180, p.atk * .6, 4, true); }  // :95
```

`phoenix` 的 `heroId` 就是 `H010`，所以 `:94` 先命中，`:95` 那个**跟随火域永远到不了它**。
实测：必杀后 `sim.fields` 长度 **0**、16 道火羽。文案也没写「留下火域」——
**是 TASK.md 的转述把默认分支的行为安到了 phoenix 头上**（与 R1g-6/R1g-8 同一类前提错误：
候选清单来自 GDD 散文而非代码）。本片按实测交付，并把这条写进队列备查。

### 5.2 觉醒**不加宽三者**，只动两项

`:40` 读 `v.rank`（火羽 3→5）、`dash` 读 `v.rank`（火径 life 2.5→4），
而 `:94` **一次都没读 `v.rank`** ⇒ 必杀两阶逐位相同（16 道）。
且火径的**半径恒为 48**，觉醒动的是**时长**不是宽度。
文案「五道火羽，延长火径」是**准确的**（用的是「延长」）；不准确的是 TASK.md 的转述。

### 5.3 敌群格的判别量是「承伤」，不是「击杀」

见 §3。这条对**后续六个形态**是通用警告：如果沿用 F01 的
`expect(control.X.killed).toBeLessThan(control.X.of)` 作为「kit 承重」的判据，
任何**能靠普攻在 10 秒内慢慢清空**的 kit 都会被误判。判据应写成**承伤或血线**。

### 5.4 150px 突进会把玩家送进 90px 站位的 Boss 体内

首领格把玩家放在 `boss.x - 90`（R1g-10 起的固定站位：在预警范围之内、61px 体接触半径之外）。
但技能的第一件事是 `dash(150, ...)`，方向 = `heroAim()` = 指向 Boss ⇒
玩家从 −90px 直接冲到 **+60px**，**落进 61px 体接触半径**。
实测 `takenBy['B001-contact'] = 32.69`（两阶相同）。

这正是 R1g-7 的 **D2 夹紧**（`min(150, distance - 65)`）想阻止的那件事 ——
而 D2 在 R1g-7 已被**单一开关反事实**打回（在 65px 站位下它求值为 0，**删掉**了突进而非缩短）。
本片**不重开这个决定**，只是记下：该失效在 `phoenix` 上复现，而且是在一个 D2 从未测过的形态上。
`bulwark` 不突进，所以它没有这条；`frostflame` 也不突进。**突进类形态（`dragon`/`phoenix`/`reaper`）共有。**

### 5.5 远程格量的是普攻射程，不是 kit

见 §3/§4.1。四片合起来看：`bulwark`/`frostlord` 的远程格读 0，是**形态设计**（近战）；
`frostflame`/`phoenix` 读非 0，但**来源一个是技能、一个是普攻**。
报告里 `kitDealt` 这个名字在 F04 的远程格是**误导性的**——它等于 `basicDealt`。
本片用 `dealtBy['H010_E'] === 0` 把它拆开断言，免得下一个读者以为 kit 参与了。

### 5.6 已有的 phoenix 断言**看着像覆盖，其实被必杀稀释**

`evolutionCombat.test.ts:29` 在**同一个测试体内**先 `sim.basic()`、再 `action('skill')` ×2、
再 `player.ult = 100; action('ultimate')`，然后才断言
`render.projectiles.length >= 5`。必杀**自己就贡献 16 道** ⇒
这条断言在**普攻一道都不射**的情况下依然为真，**它没有钉住扇形火羽的数量**。
（Scope 0 要求说明「哪些主张已被覆盖、哪些没有」——这是「以为覆盖了、其实没有」的那一类。）

### 5.7 仪器注释与代码不一致（已在本片对账）

`formPressure.test.ts` 文件头第 50-53 行写「Add one entry to `SPECS`, **one `describe` block**」，
而 `bulwark`/`frostlord`/`frostflame` **每个都有两块**（身份 + 压力）。
本片按代码的事实改成「that form's own **two** blocks」并注明是 R2-F04 才发现的对账。
（同类：R1g-11 撞到的两处「断言与注释矛盾」。）

## 6. 文案对账（Scope 5）

`evolutionCatalog.ts:17`：

- `detail: '三道扇形火羽；技能突进留下火径。'`
  - 三道扇形火羽 ✅（3 道、等间距 0.23 rad、对称）
  - 技能突进留下火径 ✅（150px 位移 + 5 个 48px 静止火径）
  - ⚠️ **未提「技能同时切一圈 150px 全周环」**。这一环是 kit 里**最大的单笔伤害**：
    精英格 `H010_E = 675.44` 全部来自它（精英在施放帧就被打死，火径一次都没 tick）。
    这不是**矛盾**（文案说的都成立），是**不完整**。
- `awakening: '五道火羽，延长火径。'`
