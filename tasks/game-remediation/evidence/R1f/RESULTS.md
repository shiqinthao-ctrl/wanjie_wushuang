# R1f：章节手机 HUD 与暂停控件

日期：2026-09-20。范围：`chapter1-v1` 手机布局与暂停弹窗；BattleView 为共享组件，
G5 旧模式仅受暂停按钮触控增强影响。分支 `codex/first-chapter-remediation`；
回退点 `3e840c1`。G5 参照 821b90c 未复核，本次不部署 Render，不打完整 R1 标签。

## 实际变化

- 首章战场 HUD 收敛为单列两行：标题/本局时间/暂停一行，生命与经验并排一行，
  目标提示与首领状态随后；击破数与本局构筑信息移入暂停弹窗。
- 暂停弹窗改为三段式：标题区固定，中间（折叠的"本局构筑"摘要 + 展开后的完整
  进化路线、战斗特效开关、声音设置）滚动，底部"继续战斗/返回大厅"固定可达；
  重新打开时构筑恢复折叠、滚动复位。
- 手机端动作按钮显示就绪/冷却秒数/充能，不再常驻键位提示；桌面（精确指针）
  仍显示 Space / E·Q / R。窄屏或粗指针下自动切换。主要目标 ≥48×48。
- 真机行为修复：已有手指按住摇杆时，第二根手指点按暂停原先无响应——
  浏览器在多指触点期间不合成 click 兼容事件。暂停按钮改用与动作键一致的
  `pointerdown` 激活（键盘 Enter/Space 走 click `detail===0` 通道，鼠标不变）。
- 章节样式集中在新增 `chapter-ui.css`（`.chapter-battle`/`.chapter-pause` 作用域），
  G5 布局与既有配色、美术不受影响；升级选择与激活守卫、规则数值零改动。

## 遗留失败（基线已存在，非本切片引入）

`settlement.spec.ts:210` 自然"角落接触败北、0 星"在 desktop 与 phone 双双失败：
英雄在 270 秒内击杀了黄巾巨将（"黄巾巨将已击败"），未如预期自然败北。
已在基线 `3e840c1`（暂存本切片全部改动并重建 dist 后）复现同一失败
（settlement-base/），证明为前序提交的战斗漂移，本切片未改任何规则与平衡。
败北 0 星的结算逻辑本身未失效（0 星守卫在规则层 1,313 项中通过）；
需要单独的平衡/测试策略任务处理，本切片不越权改平衡。
