# R3-P01（D28）—— 图鉴：一个页面，三层事实

**一句话**：图鉴读两样东西、写零样东西 —— `readChapterProgress` 给出「这份存档碰过什么」，
`save.build` 给出「这份存档的构筑有什么」。融合行的两列**各自标来源**，因为 D28 量出它们不是同一个问题。

## 1. Scope 0 的五个答案（全部命令级，详见 `DECISIONS.md` D28）

| 问题 | 答案 |
|---|---|
| `discoveries` 是什么 | `Record<formId, {discovered, awakened, cleared}>`，唯一写入点 `settlement.ts:75-78` 包在 `if (run.formId)` 里，**零读者** ⇒ 没见过 = `undefined`，不是 `false` |

## 2. 三层数：目录 → 可组装 → 本档持有

| 层 | 数 | 依据 |
|---|---|---|
| 目录行 | **10** | `fusions.json` |
| **可组装** | **4**（`F001 F002 F004 F026`） | 两部件的 A 与 P 都在 `activeSkills`/`passiveSkills` 里 |
| 死部件 | **6**（`F003 F005 F006 F020 F021 F033`） | 至少一个部件的技能不在那两张表里（**20 条进化里 11 条如此**） |
| **本档持有**（fresh） | **3**（`F001 F002 F004`） | 两部件的技能都在 `save.build` 里 |

**两列不等价，而且差在哪是可以说出来的**：`F026`（无限影军）**可组装但本档没持有** ——
它的两个部件要 `S001 + A015`（主动）与 `P039 + P024`（被动），而 fresh 存档的构筑里一个都没有。
如果只做一列，这一行就必须在「能做出来」和「你现在能做」之间选一个说谎。

**三英雄同值**：`evolutionBuild(hero)` = 起手 + 其余全部 ⇒ 三个英雄的可用技能集完全相同，
所以「可组装」按英雄切是 **4 / 4 / 4**。D21 读到的「被英雄切成两块」是**频率**的差，不是集合的差。

## 3. 页面做了什么

`src/chapter/codex.ts`（纯函数，`codexRows(save, track)`）：

- `forms: FormRow[]` —— 每行三件事：在目录里（恒真，靠 `heroForms` 提供）、**本档见过**
  （`not-found / discovered / awakened / cleared` 四态）、**需要什么**（英雄、核心术式名、
  两档等级闸门）。
- `fusions: FusionRow[]` —— 每行：两个部件（名字 + 主动名 + 被动描述）、
  `assembleAble`（技能表）、`held`（`save.build`）。
- `unknown: string[]` —— 存档里有、目录里没有的发现键，**照实报出来，不静默丢**。
- `progressError: string | null` —— `readChapterProgress` 对未来版本存档会**抛错**（`version > 1` 是
  「更旧的客户端读更新的存档」这条设计路径）。图鉴在那种存档上**不能白屏**：捕获、退回空进度、
  把原话显示出来，目录与配方照常完整。**崩溃比承认看不见更糟。**

`src/ui/CodexPanel.vue` —— 大厅「图鉴」按钮进来，顶部一个 `章节线 / 进化征途` 切换，
切的就是**两套闸门**（`legacy` Lv.3/Lv.8 与 `paced` Lv.10/Lv.19，来自 `pacingProfile`，
不是页面里的字面量）。

`src/App.vue` —— `page` 联合加 `'codex'`，大厅加一个按钮，`<CodexPanel v-else-if>` 一个分支。

## 6. 没有被验证的

- **画面没有被看见**。没有 Playwright，所以图鉴的排版、颜色、移动端折行、以及「点大厅按钮真的会换页」
  都没有被渲染验证过。被断言的是**渲染器读的那个对象**（`codexRows` 的返回值）与**源码里的四个连接点**
  （联合成员、import、按钮的 `@click`、`v-else-if` 分支）。
- 这一页**不改变任何玩法数值**，所以没有胜率/伤害读数可言。
- `未知形态` 那条横幅只在存档里有目录外的键时出现；测试造了一个假键证明它会报，但**真实存档里今天不会出现**。

## 7. 已知边界

- **`本档持有` 列说的是经典征途的账户构筑**（`save.build`），不是「本局能凑出什么」。
  进化征途里每个英雄都持有全部 10 主动 + 11 被动（`evolutionBuild`），所以那一列在征途语境下恒为真 ——
  页面上必须读作「账户构筑」，不能读成「这局能不能做」。
- **`discoveries` 只由章节结算写入**，所以「本档见过」这一列反映的是**章节线的经历**，
  进化征途里的形态选择不会进这里。这是存档结构的事实，不是这一页的选择。
- 被动技能**没有名字**（数据里只有 `skillDetails` 的描述），所以页面上被动按 `P0xx + 描述` 显示，
  没有替它编名字。
- 章节线在 UI 上**仍不可达**（`App.vue:61` 不传 `:chapter`），入口归 `R3-U06`；本页不碰它。

## 8. 本片自己踩的一个坑：全量跑到一半又改了测试文件

第一次全量在 `codex.test.ts` 还是 **15 个 `it`** 的时候启动，跑到第 1 分 25 秒时我补了
`progressError` 与第 16 条断言 —— 那份读数会对这个文件**过期**，正是 D27 刚写进 `BRIEF §7s`
的那条（「首轮全绿也可能是过期绿」）。**处理方式是杀掉重跑，不是把 15 条的绿当结论。**
所以 §4 的全量数字对应的是**最终代码**，不是「跑完就算」。

**判据复述**：跑全量前对这片改过的文件跑一次 `ls -l --time-style=full-iso`，mtime 晚于启动时刻
就重跑。这一次是**边跑边改**，比「启动时已经改完」更难发现 —— 唯一可靠的信号是**进程还活着**。
