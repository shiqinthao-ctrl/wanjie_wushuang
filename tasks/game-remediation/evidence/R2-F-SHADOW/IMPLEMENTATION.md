## 1. 决策 —— 三条修法全部否掉

`TASK.md` Scope 1 给了三条，并要求「prefer the legible rule」。**三条都不满足本片的目标。**

### 1.1 ① 的理由是假的（`QUEUE.md` #6k 原文「偏离最近目标，不再同心」）

`heroAim()` 与 `nearestFrom(player)` 的定义：

```ts
private aim(): number { const target = this.nearest(); ... }                       // nearest() 不含 Boss
heroAim(): number { const target = this.boss || this.nearest(); ... }              // CombatSimulation:174
private nearestFrom(point) { ... [...s.enemies, ...(s.boss ? [s.boss] : [])] ... } // EvolutionCombat:115
```

两者**只在「有 Boss **且** 有更近的小怪」时分离**。探针 A 在四个场景 × 五种配置上的实测：

| 配置 | `heroAim()` | `nearestFrom` | 相同？ |
| --- | --- | --- | --- |
| 敌群（12× `EN001` @120px，无 Boss） | `0.000000` | `0.000000` | ✅ |
| 远程（6× `EN002` @520px，无 Boss） | `1.570796` | `1.570796` | ✅ |
| 精英（`EN006` @120px，无 Boss） | `0.000000` | `0.000000` | ✅ |
| 只有 Boss（玩家在 Boss 旁 90px） | `0.000000` | `0.000000` | ✅ |
| Boss + 更近小怪，**同一轴** | `0.000000` | `0.000000`（`EN001` @40px） | ✅ |
| Boss + 更近小怪，**差 90°** | `0.000000`（⇒ **Boss**） | `1.570796`（`EN001` @40px） | ❌ `DIFF = -1.570796 rad` |

⇒ ① 在**四格 × 两阶**里一个字节都不动。而它唯一生效的配置（Boss + 轴上不同的小怪）**四格
里没有**（首领格 `scenarios.boss` 不撒任何小怪）。

> **方向性说明（对前一轮记录的更正）**：① 在那一配置下是**正确方向**的 —— 它让技能涡旋落到
> **Boss** 的射线上，而必杀仍在**小怪**的射线上，两者**分离**（`200 - 160 = 40 < 98.5` 的
> 圆心距 ⇒ 不再包含）。**但它在本片的目标上（敌群格可见性）没有任何作用**，而且它会在
> 真实章节（Boss 带小怪）里**未经仪器地**改变技能落点 —— 这正是 R1g-5 / R1g-6 教过的失效。

`.65` / `.397` / `.39` / `.35` 四行是**生产 harness** 的读数（每行一次 `formPressure` 运行，
报告落盘后读出）；`.45` / `.30` 来自探针 E（同口径驱动，基线四格与 harness 逐位一致，见 §7.3）。

### 2.1 两件事是**同一个事实**

**`hpMin = 1.0000` ⟺ 两阶逐位相同**，六个取值无一例外 —— 而且**在边界值 `.397` 就已经破了**，
说明这不是调参问题，是结构问题。机制可以逐条读出来：

1. 必杀 200px 盘在**第 0 帧**覆盖环上 **7/12**（`240·sin(Δ/2) ≤ 200` ⇒ `Δ ≤ 112.9°`）；
2. 剩下 **5 具**在盘外（`Δ ≥ 120°` ⇒ ≥ 207.8px），它们**自己走进**盘内；
3. 致死时，每具走进来 ⇒ **一跳即死** ⇒ 全部在 **frame 16-17** 清空（探针 E 的
   `deathFrames = [0,0,0,0,0,0,0,16,17,17,17,17]`）；
4. 不致死时，走进来的每具要 **2–3 跳**才死 ⇒ 推迟到 **frame 21-34**
   （`deathFrames = [0,0,0,0,0,9,17,21,31,34,34,34]`）⇒ **有身体在 frame 30 之后才死** ⇒
   玩家挨了 **18.68**。

⇒ **「必杀对杂兵致死」是敌群格「无伤清线」的成因**；而「必杀对杂兵致死」**同时**是技能涡旋
被遮蔽的成因。**敌群格要不了两样东西。**

### 2.2 ③ 没有让觉醒「买到东西」，它让觉醒**变负**

觉醒在敌群格的净效果（生产 harness）：

| `m` | 技能通道 `G4_WIND_E` | 分身通道 `H012_R_CLONE` | 净 `kitDealt` |
| --- | --- | --- | --- |
| `.65` | 0 → 0 | 187.63 → 187.63 | 1319.76 → 1319.76（**中性**） |
| `.397` | 0 → **277.09 → 387.93（+40%）** | 562.90 → 375.26（**−33%**） | 1845.76 → 1643.25（**−11%**） |
| `.39` | 0 → 277.09 → 387.93（+40%） | 562.90 → 375.26（−33%） | 1828.03 → 1627.73（−11%） |
| `.35` | 0 → 277.09 → 387.93（+40%） | 562.90 → 375.26（−33%） | 1726.69 → 1539.06（−11%） |

⇒ ③ 把「觉醒看不见」换成了「觉醒**把伤害从分身搬到了风阵**」，净额**下降 11%**，代价是玩家
的 18.68 血。**这不是修复，是同一类错的第四个面**（前三个：R2-F09 的守卫换分身、R1g-11 的
聚合中位数、R2-F10 的远程格普攻腰斩）。

> 顺带：`.397` 的 `G4_WIND_E` 是 **277.09 = 5 × 55.41878**、rank 2 是 **387.93 = 7 × 55.41878**
> —— 技能涡旋在敌群格的读数**只可能是「它够得着的身体数 × 一跳全额」**，与 `m` 无关（`.397`
> 与 `.30` 完全同值）。因为 `hit`（`CombatSimulation:230`）把**名义伤害**记进 `damageBy`，
> 不管身体还剩多少血 ⇒ 这一列读的是**覆盖数**，不是**有效伤害**。这正是「可达性 ≠ 伤害，
> 分开断言」的又一个实例，也是**不能用它当「觉醒变强了」的证据**的理由。

## 3. 十个形态 × 四个格 = 40 格：「无伤 ⟺ 两阶不可分」**不是**规律

本片一度想把 §2.1 写成一条**系列规律**，于是在**十份压力报告**上全量检验：

```
对每一 (形态, 格)：  clean = (hpMin(r1) == 1 and hpMin(r2) == 1)
                     blind = (dealtBy(r1) == dealtBy(r2))
```

**结果：28/40 成立，12 个反例 ⇒ 规律被证伪。** 两个方向都有反例：

| 方向 | 反例 | 机制 |
| --- | --- | --- |
| `clean=True` 但**可分** | `phoenix/horde`、`thunderlord/horde`、`void/horde`、`void/elite` | 它们的觉醒动的是**第 0 帧的离散量**：`thunderlord` 是链跳数 5→7；`void` 是技能半径 **110 → 145 跨过 120px 环**（R2-F07 已记：「一阶技能半径 110 < 敌群环 120 ⇒ 整格打空」）；`phoenix` 同类 |
| `clean=False` 但**相同** | 8 个形态的 `ranged` 格 + `thunderlord/boss` | 格里有承伤但觉醒不参与那一格 |

**而且：7/10 形态的敌群格本来就是 `clean=True, blind=True`** —— `bulwark` / `frostlord` /
`frostflame` / `legion` / `reaper` / `beastlord` / `windwarden`。**敌群格看不见觉醒是系列常态，
不是岚影的缺陷。**

⇒ 这把结论钉死了：
- **`windwarden` 不是异类**，它在敌群格的读法与多数形态一致；
- 它能看见觉醒的形态，靠的是**觉醒改变第 0 帧的离散量**（跳数 / 跨环半径），而**岚影的觉醒
  是「半径 120→160 + 时长 4→6」**，两项在**环上都是第 0 帧中性**的（`240·sin(45°) = 169.7 > 160`
  ⇒ 160px 盘在 30° 离散环上**一具都不多**）；
- 所以「敌群格看不见岚影的觉醒」**不是遮蔽造成的**（遮蔽只是让读数从 277.09 变成 0），
  **根子是觉醒本身不动第 0 帧**。R2-F10 的 `horde` 断言「the awakening cannot show here」
  **按字面仍然正确**。
