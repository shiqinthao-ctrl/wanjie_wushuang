# USER_REQUEST_TIMELINE.md
# 用户需求时间线（项目相关）

本文件记录项目开发过程中用户反复确认的方向，供后续开发者理解“为什么这样设计”。

1. 要求制作包含三国、水浒、西游、忍界、大航海、灵界、气武元素的割草游戏。
2. 明确要求养成、天赋、符文、羁绊、宠物、道具系统。
3. 要求扩充技能：主动、被动、增益等，不接受技能数量过少。
4. 要求完整技能树 + 进化图谱。
5. 多次要求“下一步 / 下一版”，持续从设计推进到可运行HTML。
6. 要求先输出一般前端HTML。
7. 要求美化界面。
8. 持续推进战斗、地图、Boss、英雄、Build、成长、世界、技能等版本。
9. 后期要求不只是展示：技能、英雄、Boss、装备、符文、宠物必须真实进入战斗。
10. 要求Boss多阶段、地图互动、掉落选择、刷宝动力。
11. 要求长期成长：等级、星级、熟练、觉醒、天赋。
12. 要求七模式真正可玩，而非只是按钮。
13. V3.0开始强调稳定与收口，不继续无限堆一级系统。
14. 用户准备使用 Codex 正式开发，要求直接生成可运行可交付的工程。
15. 要求 Codex 开发包，包括产品规格、验收、任务、规则。
16. 反馈 Codex 经常出现 413 / prompt limit，要求优化上下文。
17. 再次要求检查包完整性，必须包含全部项目对话过程及结果。
18. 当前策略确定为：完整母包 + Codex轻量入口，两者同时存在。
