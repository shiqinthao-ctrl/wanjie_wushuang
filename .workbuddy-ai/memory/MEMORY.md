- **「开关存在」≠「能触发」**：为 0 的开关比没有更糟。断言默认窗口恒 0 + 真测量另开**显式窗口**。**窗口长度决定可见性**：节奏驱动的事件到不了就拉长（从配置读、按场景覆写）或写成已知边界。
- **生产字段 > 近似**；基准先钉再乘（绝对覆写须在乘数前）；`undefined`=不动；**反解参数从运行实际用的字段读回**。
- **「读数是一个连续量」是最贵的默认假设**：先问**最小增量**。`taken` 看着像伤害总量，实为**命中次数 × 单次接触伤害** —— 320 个样本**全**落在 `11.52*(1-14/(14+60)) = 9.34054054054054` 的整数倍上（`enemyDamage.EN001` 经 threat-v2 软上限，`combatMath.ts:146`）。**离散量上的读数不给中间档**，只能交付**那张表**；若最小增量是 1，则「挑一个更好的值」**不可表达**。**每个量都先问「它是什么的单位」**。
- **「扫描床上恒定」是必须测量的断言，不是可继承的前提**：队列假定控制臂在半径带上恒定，实测**不恒定** —— `reaper` 干净集 `DDCCCDCC`（120/240 脏、其余干净，两处同为 3 次接触）。**非连续的结果集 = 测的不是距离**（距离给区间、竞态给点集）⇒ **一个非连续集合是「这不是距离阈值」的证明**，不是数据脏。
- **「既有仪器覆盖它」要分臂数一遍、再分轴数一遍**：队列说「带上没有对应物」**一半是假的** —— kit 臂早有完整带（`radiusSweep()`，已断言 `[120]` 唯一），缺的只有**控制臂** ⇒ **本片独立重算的结论在仓库里早已存在**。**一条扫描床可能只覆盖它名字里一半的臂。**
- **写「重块要显式超时」的切片自己也踩了它**：`band()` 320 次 `run()`（十形态 × 八档 × 两阶 × 两臂）默认 5s ⇒ 全量红、单独 5.4s 绿（工作 2.7s）= 又一例**并行争抢**。**修法是两条**：**① 记忆化**（`cached ??= build()`，320 次只算一次而非四块各一次）**② 显式超时**（`300_000`）。只加超时会在块数增长时重淹，只记忆化会在单块变重时重淹（整文件 29.17s → 21.40s）。

- **「两个读数不同」要问到「是不是子集」** ⇒ 子集关系直接点名**哪一半被漏掉**（GDD 的 G8 字面两个键 12,098,521 ⊂ 桶读数 33,139,229，漏掉的正是 `manual` 旗标判为 `true` 的那一半 = 指标存在的理由）。

- **「同形两义」要问「谁减掉谁」**：`G2_FROST_E` 同时是签名场与 `G2_FROST` 的释放键，但 `frostflame` 的 core 也是 `G2_FROST` 而 kit 用 `G5_*` ⇒ **同一形状过滤器能抓到它** ⇒ 撞车 = 「那个字符串落在**会被减掉**的那一半里」，不是「有共同的字符串」。**守卫盲 ≠ 数据丢了**：`dealtBy` 键集不变、释放**并进**签名场自己的键（152.92→1136.01，**7.43×**）；**「靠构造回避」只写在散文里 = 没有断言**（把五个装配各断言一次）。

- **反解出来的量不是「遭遇的性质」**：`phaseOfRaw`（`bossThreat.test.ts:79-82`）把相位**从伤害数额反解** ⇒ `phase1` 空是**数值事实**，不是「战斗没进 phase 1」；兄弟三元返回 `null` 时要问是「没测到」还是「测到且不合格」（这里两者同值，`true`/`false` 都不可达）。

- **一个旋钮渗进正交维度 = 顺序成了另一个变量的函数**：`:70` 的相位是**难度**旋钮（伤害/预警/速度/冷却都按它缩放，合法），`:106` 把它**加进招式下标** ⇒ 顺序随**血量**（= DPS）走。**判据不是「它有没有用」而是「它作用在哪个维度」**：把 `phase` 从索引拿掉，「相邻两刀永不重招」**依然成立**（靠 `+1 % 3`）⇒ **相位项在那里没有防守对象**。凡「同一输入在不同时刻解析出不同输出」的映射，先问**那个耦合两者的加法**在防什么。
- **注释的归因可能是错的**：`bossThreat.test.ts:249-250` 声称「后缀永不连续重复」靠 `(skillIndex + phase - 1) % 3`，实际只靠 `+1 % 3` ⇒ **注释声称的机制 ≠ 代码实际依赖的机制**；解释一条性质前先**把那个性质的最小充分条件找出来**。
- **读回的字段要先确认它是什么**：`castLog` 记的是 `event.shape`（**形状键** `'cone'`）**不是**招式名（`'旋风断军'`）；混用会让反事实算出 **61/61**（一个看起来很有力、实际是假的读数）。**修法不是改数，是把返回「键」与返回「名」拆成两个函数**（名用于表/断言，键用于与生产比较）。**任何「拿生产字段和期望值比」的地方，先把那个字段打印出来看一眼。**
- **反事实要钉实测值，不要钉阈值**：断言 `[61, 58]` 与 `[59, 59]`（跑出来的）而不是 `moved > 0.9 * total`。**阈值只证明「有变化」，实测值证明「变化是多少」** —— 后者在规则被改动时会指出移动了哪一格，前者只会说「还是红的」。
- **「四个格覆盖了四种威胁」是清单不是覆盖** ⇒ 格名对了不代表**格的产物对了**：四个压力格里三个有身体没 Boss、一个有 Boss 没身体，而**发货的整个 Boss 阶段两者同时在场**（`bossPhaseSpawnInterval` 是**乘数不是开关**，`CombatSimulation:341-342`）⇒ 每个 Boss 数字都量在游戏从不展示的战斗里。**「每个风险都有一个格」要问的是「那个格装的东西是不是游戏里真有的组合」**，不是「有没有这个格」。**数一遍那个集合**（四格 × 十形态 = 40，`framesBoth` 恒 0）比读格名有用。
- 具名分支读**它自己那一行**，确认前一条是 `if` 还是 `else if`；**「已有断言」可能假覆盖**；**不要用新机制修只在特定数值下出现的症状**。
- 新形态先问**伤害落在哪个容器**（`fields`/`vortices`/`summons`/`projectiles`）再选读数；不沿用上一形态的键；**身份测试成对**。

## 判定 / 取舍
- **「有效」≠「修好了」**：候选修法逐条写清「机制生效」与「净额变好」，净额符号用**同一份账本**回答。
- **「两个读数各自正确、基准不同」**：同问题在两棵树上答案不同 ⇒ **先标基准，「TASK 写错」是最后一种可能**；**扫掠下同步翻转的两个读数 = 同一事实的两面 ⇒ 出路是换场地不是换数值**；**一个杠杆可同时改两个验收且方向相反 ⇒ 按策略拆开报**。
- **「A 就是 B」的等号要被测量**。**「几何理由」先确认两个量是否同源**：队列的「站位 90 > 半径 70 ⇒ 打不中」把「到 Boss 的距离」当成「到圆心的距离」，而圆心 = 玩家 ⇒ 实测 `distAtCast` 恒 0。
- **「到达」≠「命中」**（`.75×` 下 `hud` 命中 0 但到达 8 次）⇒ 报红时先问它测的是「事件发生」还是「事件生效」。**「没观测到」可能是节奏而非结构** ⇒ 宣布不可测前先把**所有已有的臂**跑一遍（不读线索的臂行为不同）。**`filter(x>0)` 会让零命中静默消失** ⇒ 取极值前先问被滤掉的是什么；三元返回 `null` 的分支要问是「没测到」还是「测到且不合格」。
- **「这个 kit 如此」与「系列如此」分开写**（n=40 曾证伪）。**觉醒要「看得见」就得动第 0 帧的离散量**（跳数 / 跨环半径）；半径+时长类改动在离散环上可能是第 0 帧中性的。
- **注释声称的读数 ≠ 代码实际算的**（键集不同 ⇒ 差 2.74×）；**描述性断言没人断言 ⇒ 最易烂**。
- **判「哪个口径才对」用「两个读数是否朝同一方向动」**：反向 ⇒ 测的是**别的东西**，不是「更保守的口径」（`evolution/unlock`：`r(进化数, gddShare)` = **−0.32** vs `r(进化数, manualCoreShare)` = **+0.34**）。**一个随玩家变强而下降的「贡献」读数，测的不是贡献。** 裁定按**意图**，并把**保守界**记进账（release-only = 0.22174，未达 35%）——**口径不能在两种读法之间来回挑**。
- **设计文档里的断言没人执行 ⇒ 最易烂**（GDD §11.1 的 G8 片段错了整整两片，harness 的守卫只记「差 2×」而没点名机制；**全库没有任何测试或脚本读 GDD 文本**）。**改设计文档是「免费的文档半边」**：先确认门禁（`archive-verify` 必需清单 / 活跃上下文包 / `doc-budget`）不包含它，再落。
- **「靠构造回避」要留断言**；**修分类器 vs 修生产**：生产后缀的用途声明被实测满足 ⇒ 改后缀只改键名、买不到新东西。
- **「互斥 / 不可能 / 永远」是先验，不是测量** ⇒ 先把那个集合**数一遍**再逐个成员跑一遍（敌群格「无伤 ⟺ 两阶不可分」被 **40 格 12 反例**证伪，两个方向都有；TASK 的「八个形态」实为 **7 处**）。**「互斥可破」≠「随便挑个数」**。
- **一个读数可对参数非单调**（`clean` 对半径 `[T,T,F,T,F,T,T,T]`）⇒「挑一个好值」不是设计：单调的钉一个数，**非单调的必须连同那张表一起交付**。
- **行号引用会随插入位移** ⇒ 会被行号引用的文件里加仪器**一律追加到文件末尾**，并用**断言**钉住「新常量 == 旧构造」（共享字面量只证明两处写的一样）。
- **「最弱的那一格」要用同口径数出来**（敌群 7/10 盲 < `ranged` 8/10 < `elite` 9/10）⇒ 别拿直觉当定位。
- **「几何理由」要写成可判定的不等式，并逐格对账**：队列的「偏离最近目标」不可证伪 ⇒ 化成 `d < standoff && standoff + min(reach, d) > r + bossR`，**模型解释 46/46 格才算结论**；对不上的那几格才是要看的地方。**挡路的可能是站位而不是半径**（出货 90px 下 rank 2 的可分离集合 = **空集**）。
- **离散量上的增益是常数 ⇒ 别找中间档**：① 买到恒 **+831.28 / +1219.21**（跳数 × 单跳伤害）⇒ 一格要么全盲要么全开。作用在跳数/环上命中数/分身数这类离散量上时，先扫区间确认是不是常数，再问**占比**（本片 = Boss 预算的 **0.18% / 0.27%** ⇒「可验证但不值得落地」）。

## 文档 / 门槛 / 证据
- **门槛写比率或序关系**；**先读注释再读代码**，矛盾按注释本意改；**复合断言须能从某行数据推出**；**门槛的「字面读数」要跟 GDD 原文对**；**「pin every X」要逐项数清单**。
- **临时探针必须与正式块一起核，且「文件行数对不上」是唯一的信号**：探针用 `cat >>` 追加、收尾用 Python 截断，**漏截一次就会让全量套件跑在探针代码上**（本片 `formPressure.test.ts` 残留 PROBE3 = `+6` 而非 `+5`；`survivability.json` 也留在证据目录）。**修法三条**：① 落地前 `grep "TEMP PROBE\|describe('PROBE"` 必须空；② 探针写的证据文件要么进账要么删净（本片 `survivability.json` **不进账** ⇒ 删）；③ **全量套件的 `+N` 与「本片新增 `it` 数」对不上时先当作探针残留查**，别改文档去迁就数字。
- **「从源码派生」的分类器认的是字面调用形状，不是你的意图**：`byte-ledger.mjs` 扫 `writeFileSync(resolve(<dir>, '<name>'))` ⇒ **别名 import**（`{writeFileSync: write}`）、**预绑定全路径 const**、**三参 `resolve(ROOT,'DIR','x.json')`** 三者都不匹配 ⇒ 新报告被判成**冻结**（将来合法重写会以 `MOVED(frozen)` 报红）。**修法照抄该文件既有形状**（`const dir = resolve(EVIDENCE_ROOT,'R2-F-XXX')` 再 `writeFileSync(resolve(dir,'x.json'))`）。**且扫描器连注释一起读** ⇒ 把调用形状写进散文会凭空造出假报告名（本片先后出现 `<name>`、`name.json`）⇒ **改完要 `ledger:coverage` 数名表，不只看总数**。仪器切片自己的出口也要按仪器标准核。
- **并发多个 `Edit` 可能静默丢一个** ⇒ 改完 `grep` 复核。
- **滚动报告属于当前代码**：迁到当前切片目录、旧目录留指向；零生产改动不重指输出目录；标注「每次运行被覆写」；**schema 变用「去新键重建 md5」**，没变才直接 md5。
- **逐字节账要写成可执行清单，不能手抄**（D17 实测更正）：`R1g-12/` 有 **11 份**滚动 `.json`，而**真正的缺口是「没有一片重走那棵树」** —— `evidence/**/*.json` **261** vs 账本 **248** ⇒ **13 份从未进账**（6 滚动 + 7 冻结）。**「核对了清单」≠「核对了树」**；**漏掉的项不报错、只沉默**。修法 = `byte-ledger.mjs` 走树生成 + `byteLedger.test.ts` 守门（**独立重算分类** = 守卫的守卫）。
- **滚动 vs 冻结必须由源码派生，不能靠 mtime**（全量套件会把滚动报告全部重写、洗白 mtime）⇒ 判据 = `grep writeFileSync(resolve(<CONST>, '<name>'))`；**26 滚动**（16 直接 + `formPressure` 表驱动 10）。**分类是断言，不是注释。**
- **schema 长大的 md5 有两个用法，不能混**：**相等性**检查用「**去新键 + `sort_keys` 重建**」（否则把「数值没变的刷新」误判成「文件变了」）；**覆盖率**账本用**明文直接 md5**。混用**两个方向都错，且都不报错**。
- **覆盖声明要与数字同句，且由命令产出**：`248` 那句散文**没有任何命令支撑**、存活十天（**全库没有测试或脚本读它**）。**修法不是改数字，是换掉产生它的方式** —— 生成器 + `npm test` 的门 + 守卫的守卫三层，缺一层就回退。
- **同一个量在不同基准下有不同值 ⇒ 必须标基准**；**改值要 `grep` 全库**，分历史记录（不改）与当前值（必改）。
